# Diss-Outline — 学位论文逐章扩写大纲

读取源英文论文（manuscript.tex + idea.md）和 diss-init 创建的章节骨架，**逐章交互式**生成详细的写作大纲。产出的大纲为 `/diss-draft` 提供无歧义的写作输入。

**本 skill 不写正文**，只产出结构化的写作要点和内容映射。

## 参数解析

从 `$ARGUMENTS` 识别目标项目或章节。

- 如果在 `dissertations/` 某个子目录下运行：自动检测当前项目
- 如果提供了学生姓名（如 `车茜`）：在 `dissertations/` 下查找匹配的文件夹
- 如果提供了章节号（如 `ch3`、`第三章`）：只处理该章
- 否则：列出 `dissertations/` 下所有项目，用 AskUserQuestion 让用户选择

## 步骤 0：前置准备

### 0.1 读取项目 CLAUDE.md

从项目 CLAUDE.md 提取：
- `源项目路径`（指向 Zylen paper 或 _gym paper 下的英文论文项目）
- `学位论文章节结构`（diss-init 生成的完整三级标题 + 字数分配表）
- `学位类型`（硕士/本科）
- `项目阶段`

### 0.2 读取源英文论文

从源项目读取：
- `manuscript.tex`：完整英文正文（提取每个 section/subsection 的文本内容）
- `idea.md`：RQ、Gap、方法框架、核心贡献
- 源项目 CLAUDE.md：项目概况

**构建英文论文内容索引**：
```
Section 1: Introduction → 行号范围 [L10-L85]
Section 2: Literature Review → 行号范围 [L86-L150]
  2.1 xxx → [L90-L120]
  2.2 xxx → [L121-L150]
Section 3: Methodology → 行号范围 [L151-L280]
...
```

### 0.3 读取章节骨架

读取 chapters/ 下所有 .tex 文件，提取已有的三级标题和注释（目标字数、内容来源标注）。

### 0.4 确定处理范围

- 如果 `$ARGUMENTS` 指定了章节号 → 只处理该章
- 否则 → 向用户展示全部章节列表，询问：
  - 逐章处理（推荐，从第一章开始）
  - 指定某一章开始

## 步骤 1：逐章生成大纲（核心循环）

对每一章执行以下流程。**每章完成后必须等用户确认，才进入下一章。**

### 1.1 展示章节概览

向用户展示当前章节的：
- 章节标题与全部三级标题
- 各节目标字数（来自 diss-init）
- 各节内容来源标注（改写/展开/新增/重组）

### 1.2 逐节生成写作大纲

对当前章节的**每个三级标题**（`\subsection`），生成以下结构化大纲：

```markdown
### X.Y.Z 三级标题

**目标字数**：XXX 字

**内容来源**：改写（← English §3.2）/ 展开（← English §2.1，需补充原理）/ 新增 / 重组

**写作要点**（根据目标字数调整，约每 300-500 字一条）：
1. [要点1]：一句话描述这段要写什么，包含关键论证逻辑
2. [要点2]：...
3. [要点3]：...
（1000字以下 3-4 条，1000-2000字 4-6 条，2000字以上 6-10 条）

**参考段落**（仅限改写/展开类型）：
> [引用 manuscript.tex 中对应的英文原文段落，标注源 section 编号]
> — Source: §X.Y, L100-L120

**关键术语对照**：
| English | 中文翻译 | 备注 |
|---------|---------|------|
| xxx     | xxx     | 本文采用的译法 / 学界通用译法 |

**写作注意**：
- [该节的特殊要求，如：需补充国内案例/需引用中文文献/需绘制示意图等]

**图表需求**（如本节无图表需求，标注"无"）：
- [ ] 图X.Y：{描述}（类型：TikZ概念图/Python数据图/R统计图）
- [ ] 表X.Y：{描述}
```

### 1.3 章节类型专属规则

不同章节类型有不同的中文学术写作惯例，生成大纲时必须遵循：

#### 第一章 绪论

- **1.1 研究背景**：必须从宏观到微观递进，新增国内行业数据和政策背景（英文论文通常没有）
- **1.2 研究目的及意义**：理论意义和实践意义必须分条列点，每条 2-3 句
- **1.3 研究范围及内容**：需包含「全文地图」——逐章概述每章做什么
- **1.4 研究方法与技术路线图**：需标注"新增：技术路线图（flowchart）"
- **1.5 本章小结**：固定格式，2-3 句概括本章内容

#### 第二章 文献综述及理论基础

- 每个综述方向需标注：概念界定 → 研究现状 → 研究不足
- **理论基础节**：需展开讲理论起源、核心观点、在本研究中的适用性（英文论文通常一笔带过）
- **研究现状述评**：必须明确指出 Gap，与 idea.md 中的 Gap 一致
- 标注哪些文献需要补充中文来源（CNKI）

#### 第三章 研究设计/模型构建

- **方法原理**必须单独成节并充分展开（英文论文假设读者懂，学位论文不能）
- 变量定义表、数据来源说明需比英文论文更详细
- 模型公式需逐步推导，不能像英文论文那样跳步

#### 核心研究章节（第四、五、六章等）

- 每章对应 1-2 个 RQ，大纲中必须标注 RQ 映射
- 结果呈现：标注需要的图表清单（表X.X、图X.X）
- 结果讨论：标注需要对比的已有研究（从 literature review 中提取）

#### 对策建议章

- 通常为**新增**内容（英文论文的 Implications 只有 1-2 段）
- 每条建议需包含：问题诊断 → 对策内容 → 实施路径
- 建议维度需与研究发现一一对应

#### 结论章

- 主要研究结论按 RQ 逐条总结
- 创新点 3-4 条，需与绪论中的研究意义呼应
- 研究不足与展望：诚实列出局限性

### 1.4 用户确认

以完整 markdown 格式展示当前章节的所有三级标题大纲，用 AskUserQuestion 请用户确认：
- 确认无修改 → 保存并进入下一章
- 需要修改 → 根据反馈调整后重新展示，再次确认

## 步骤 2：保存大纲

### 2.1 保存方式

每章确认后，将大纲保存到对应章节的 outline 文件：

```

  ch1.tex          ← diss-init 创建的骨架
  ch1_outline.md   ← 本 skill 生成的大纲（新建）
  ch2.tex
  ch2_outline.md
  ...
```

**文件格式**：

```markdown
# 第X章 章节标题 — 扩写大纲

> 生成时间：YYYY-MM-DD
> 源项目：{源项目路径}
> 总目标字数：X,XXX 字

---

## X.1 二级标题

### X.1.1 三级标题

**目标字数**：XXX 字
**内容来源**：改写（← English §X.X）
**写作要点**：
1. ...
2. ...
3. ...

**参考段落**：
> ...

**关键术语对照**：
| English | 中文翻译 | 备注 |
|---------|---------|------|
| ...     | ...     | ...  |

**写作注意**：
- ...

**图表需求**：
- ...（或"无"）

```

### 2.2 Git Checkpoint（每章确认后）

```bash
git add chapters/ch{N}_outline.md chapters/ch{N}.tex && git commit -m "diss-outline: ch{N} outline confirmed"
```

### 2.3 同步更新 ch*.tex 注释

在对应 .tex 文件的每个 `\subsection` 下方，追加或更新简要注释：

```latex
\subsection{X.1.1 三级标题}

% 目标字数：XXX字
% 内容来源：改写（← English §X.X）
% 写作要点：(1) xxx (2) xxx (3) xxx
% 详细大纲见 ch1_outline.md
```

## 步骤 3：生成总览摘要

所有章节大纲完成后，生成 `outline_summary.md`，包含：

### 3.1 内容来源统计

```markdown
## 内容来源统计

| 来源类型 | 节数 | 占比 | 目标字数合计 |
|---------|------|------|------------|
| 改写    | XX   | XX%  | X,XXX      |
| 展开    | XX   | XX%  | X,XXX      |
| 新增    | XX   | XX%  | X,XXX      |
| 重组    | XX   | XX%  | X,XXX      |
| **合计** | XX  | 100% | ~XX,XXX    |
```

### 3.2 英文论文 → 学位论文映射表

```markdown
## 内容映射表

| 英文论文 Section | 学位论文对应节 | 处理方式 |
|-----------------|--------------|---------|
| §1 Introduction | 1.1, 1.2     | 改写+展开 |
| §2 Lit Review   | 2.1-2.4      | 展开    |
| §3 Methodology  | 3.1-3.4      | 展开    |
| —（无对应）      | 1.3, 1.4, N-1章 | 新增 |
| ...             | ...          | ...     |
```

### 3.3 关键术语总表

汇总所有章节的关键术语对照，去重后生成统一术语表：

1. **写入项目 CLAUDE.md**（`## 术语表` section）——此为术语表正本，后续 /diss-draft 和 /diss-polish 均从此处读取
2. 在 `outline_summary.md` 中保留副本，标注"正本在项目 CLAUDE.md"
3. 确保全文翻译一致，同一英文术语对应唯一中文译法

### 3.4 图表清单

汇总所有章节大纲中的图表需求，按类型分类（TikZ概念图 / Python-R数据图 / 表格），附合计数。此清单为后续图表准备（③.5 步骤）的输入。

### 3.5 新增内容清单

列出所有标注为「新增」的节，提醒用户这些部分需要额外准备素材：

```markdown
## 新增内容清单（需额外准备素材）

- [ ] 1.1.1 研究背景（宏观）→ 需补充：国内行业数据、政策文件
- [ ] 1.4.2 技术路线图 → 需绘制：全文技术路线 flowchart
- [ ] 3.2 方法原理 → 需补充：方法的理论推导和发展历程
- [ ] N-1章 对策建议 → 需补充：结合国内实际的管理建议
- ...
```

## 注意事项

- **交互优先**：每章大纲必须经用户确认后才保存，才进入下一章。不可批量生成后一次性展示
- **不写正文**：本 skill 只产出大纲要点（bullet points），不写任何正文段落。正文由 `/diss-draft` 完成
- **要点粒度**：根据目标字数动态调整。参考标准：每 300-500 字一个要点（1000 字以下 3-4 条，1000-2000 字 4-6 条，2000 字以上 6-10 条）。每条要点 = 1 个核心论述点（1-2 句话描述），不是模糊的主题词
- **术语一致性**：同一英文术语在全文中必须使用统一的中文翻译，大纲阶段就要锁定
- **来源标注必须精确**：改写/展开类型必须标注英文论文的具体 section 编号和行号范围，不能含糊
- **参考段落完整引用**：改写/展开类型的参考段落必须引用 manuscript.tex 的原文，不能概述
- **章节类型规则不可省略**：步骤 1.3 中各章节类型的专属规则是硬性要求，不是建议
- **不修改章节骨架**：diss-init 确认的三级标题结构不可在本 skill 中修改。如果发现结构问题，提示用户重新运行 `/diss-init` 调整
