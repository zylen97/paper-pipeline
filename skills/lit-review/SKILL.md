# Lit-Review — 文献分析与筛选

对用户提供的RIS文件进行系统性分析，通过并行subAgent逐方向筛选，生成方向报告和总报告，最终精简文献池。

**输入** `$ARGUMENTS`：可选，指定处理哪些方向。示例：
- `/lit-review` — 处理所有有RIS文件的方向
- `/lit-review 1,3,5` — 只处理方向1、3、5
- `/lit-review 2` — 只处理方向2

---

## 步骤 0：前置检查与上下文加载

### 0.1 检查检索方案
- 读取 `structure/2_literature/literature_search_plan.md`
- 不存在 → 停止，提示用户先运行 `/lit-plan`
- 提取：`{TOTAL_BUDGET}`（总预算）、方向列表、每方向的功能标签、配额、优先级

### 0.2 加载研究上下文
- 读取 `CLAUDE.md` → 项目编号、标题、方法、目标期刊
- 读取 `structure/0_global/idea.md` → RQ、Gap、方法论、贡献意图
- 从 `literature_search_plan.md` 头部提取 `{IDEA_MATURITY}`（mature / exploratory）
- 将以上浓缩为 `{RESEARCH_CONTEXT}`（≤ 800字），包含：
  - 论文标题与一句话概括
  - RQ简述（如有；exploratory模式下可能没有，写"待文献分析后确定"）
  - 方法论框架（如有）
  - 核心矛盾/机制（如有）
  - 目标期刊

### 0.3 扫描RIS文件
- Glob `structure/2_literature/*.ris` → 列出所有RIS文件
- 将RIS文件与方向匹配（按文件名中的方向编号或关键词）
- 如果 `$ARGUMENTS` 指定了方向 → 只处理指定方向
- 统计每个RIS文件的条目数量（通过计数 `TY  -` 行）
- 无RIS文件 → 停止，提示用户从WoS下载

### 0.4 检查已有报告
- 对每个待处理方向，检查 `directionX_*.md` 是否已存在
- 已存在 → 提示用户：是覆盖还是跳过？等待确认

### 0.5 展示处理计划
在对话中展示：

```
待处理方向：
| # | 方向 | RIS文件 | 条目数 | 配额 | 状态 |
|---|------|---------|--------|------|------|
| 1 | XXX  | 1_xxx.ris | 445篇 | 50篇 | 待处理 |
| 3 | YYY  | 3_yyy.ris | 173篇 | 40篇 | 待处理 |
预计调用 {N} 个并行subAgent
```

等待用户确认后继续。

## 全局约束：SubAgent负载上限

**AGENT_ITEM_LIMIT = 50**

单个subAgent处理的文献条目数不得超过50篇。超过时必须拆分为多个subAgent并行处理。此约束适用于步骤1中所有RIS筛选任务。

---

## 步骤 1：并行调度SubAgent分析

### 1.0 拆分判断

对每个待处理方向，检查其RIS条目数（步骤0.3已统计）：

- **N ≤ AGENT_ITEM_LIMIT (50)**：该方向分配1个subAgent
- **N > AGENT_ITEM_LIMIT**：按以下规则拆分：
  - 50 < N ≤ 100：拆为2个subAgent，每个处理约 N/2 条
  - 100 < N ≤ 150：拆为3个subAgent
  - N > 150：拆为 ⌈N/50⌉ 个subAgent

拆分方式：按RIS文件中的条目顺序均匀分割（每个subAgent处理连续的一段条目）。

**所有subAgent（含拆分后的）同时并行启动**（在同一条消息中发出所有Agent tool calls）。

### 1.1 展示最终调度计划

```
调度计划：
| Agent# | 方向 | 条目范围 | 条目数 | 配额分配 |
|:------:|:-----|:---------|:------:|:--------:|
| 1 | 方向1 | 1-50 | 50 | 按比例 |
| 2 | 方向1 | 51-100 | 50 | 按比例 |
| 3 | 方向2 | 1-45 | 45 | 全部配额 |
| ... |
```

> **配额分配**：当一个方向拆分为K个agent时，该方向配额按比例分配给每个agent（方向配额/K，向上取整）。最终合并时由主Agent按方向总配额截断。

### 每个SubAgent的Prompt模板

```
你是一个学术文献分析专家。请分析以下RIS文件中的文献，为一篇学术论文的文献综述做筛选。

## 研究背景
{RESEARCH_CONTEXT}

## 当前分析方向
- **方向编号**: {方向编号}
- **方向名称**: {方向名称}
- **层面**: {层面}
- **论文角色**: {论文角色说明}
- **配额**: {配额}篇（核心≤{x} / 重要≤{y} / 备选≤{z}）

## 分级标准
- **核心（Core）**: 必须引用。与本研究直接相关，是理论基础、方法论先例或直接竞品
- **重要（Important）**: 大概率引用。相关度高，提供重要背景或对比
- **备选（Backup）**: 可能引用。有一定相关性，可在需要时补充

## 任务
1. 读取RIS文件：{RIS文件路径}
2. 逐篇分析每条文献的标题、摘要、作者、期刊、年份
3. 判断每篇文献：
   a. 与本研究的相关度（高/中/低/无）
   b. 分级（核心/重要/备选/淘汰）
   c. 入选理由（1-2句话，说明为什么相关、在论文中扮演什么角色）
4. 淘汰相关度为"无"的文献
5. 按配额筛选：核心≤{x}篇，重要≤{y}篇，备选≤{z}篇
6. 如果高相关文献超出配额，优先保留：高被引 > 近5年 > 顶刊 > 方法论对标

## 输出格式

严格按以下Markdown格式输出，不要遗漏任何字段：

```markdown

> **淘汰**: {淘汰数}篇

---

## 筛选标准
{列出该方向的具体筛选标准}

---

## 核心文献（Core）— {a}篇

### {子类别名称}（{n}篇）

| # | 作者 | 标题 | 年份 | 期刊 | 入选理由 |
|:--|:-----|:-----|:----:|:-----|:---------|
| 1 | ... | ... | ... | ... | ... |

{按子类别分组，每组一个表格}

---

## 重要文献（Important）— {b}篇

{同上格式}

---

## 备选文献（Backup）— {c}篇

{同上格式，入选理由可简短}

---

## 淘汰文献摘要

淘汰{淘汰数}篇，主要原因：
- {原因1}：约{n}篇（如：纯技术实现，无战略/管理视角）
- {原因2}：约{n}篇
- ...

---

## 方向小结

- **该方向对论文的核心价值**: {1-2句话}
- **分级分布**: 核心{n}篇, 重要{n}篇, 备选{n}篇
- **潜在竞品**: {列出与本研究高度相似的文献，如无则写"未发现直接竞品"}
- **补检建议**: {该方向是否有遗漏，是否需要补充检索}
```

将输出保存为 `structure/2_literature/direction{N}_{方向名称简写}_report.md`

### SubAgent的RIS读取策略

由于拆分后每个subAgent最多处理50条RIS条目，直接一次性读取全部分配的条目即可。

## 步骤 2：汇总与跨方向分析

所有subAgent完成后，主Agent执行以下操作：

### 2.1 读取所有方向报告
- 逐一读取每个 `directionX_report.md`
- 提取所有入选文献（核心+重要+备选），构建全局文献表

### 2.1b 同方向多Agent合并
当某方向被拆分为多个subAgent时，各subAgent各自输出独立的筛选结果。主Agent将同方向的结果合并：
1. 汇总所有入选文献
2. 按分级+入选理由质量重新排序
3. 按该方向的**总配额**截断（核心≤x, 重要≤y, 备选≤z）
4. 生成该方向的完整 direction report（格式不变）

### 2.2 跨方向去重
- 以（第一作者姓氏, 年份, 标题前30字符）为去重键
- 同一文献出现在多个方向 → 保留最高分级，合并功能标签
- 输出去重统计：去重前{X}篇 → 去重后{Y}篇，重复{Z}篇

### 2.3 全局统计
```
| 分级 | 数量 |
|:-----|:----:|
| 核心 | {n} |
| 重要 | {n} |
| 备选 | {n} |
| **合计** | **{N}** |
```

> 注：功能标签统计由后续 `/lit-tag` 完成。

### 2.4 总量检查
- 去重后总量 ≤ `{TOTAL_BUDGET}` → 通过
- 去重后总量 > `{TOTAL_BUDGET}` → 需要跨方向再平衡：
  1. 优先削减P2/P3方向的备选文献
  2. 再削减P1方向的备选文献
  3. 最后削减重要文献（需逐篇判断）

## 步骤 5：清理RIS文件

用户批准后：
1. 对每个方向的RIS文件，保留入选文献（核心+重要+备选），删除淘汰文献
2. 清理方式：读取RIS → 按入选列表过滤 → 覆写原RIS文件
3. 清理完成后报告：每个方向清理前后的条目数

> **注意**：RIS文件按 `TY  -` 开头分割条目，每条到 `ER  -` 结束。匹配依据为 `TI  -`（标题）字段。

## 边界条件处理

| 情况 | 处理 |
|:-----|:-----|
| literature_search_plan.md 不存在 | 停止，提示先运行 `/lit-plan` |
| 某方向无对应RIS文件 | 跳过该方向，在对话中提示 |
| RIS文件为空或格式异常 | 跳过，报告错误 |
| 某方向入选文献数 < 10 | 警告引用池可能不足，建议补检 |
| 某方向发现直接竞品 | 在对话中**立即预警**，不等到总报告 |
| subAgent超时或失败 | 报告失败方向，继续处理其他方向 |
| 已有方向报告 | 按步骤0.4处理（覆盖/跳过） |
| 去重后超预算 | 按步骤2.4的优先级削减 |
| idea.md 不存在 | 停止，提示先完善 idea |
