# Fund Draft — 基金申请书逐节撰写

基于 `/fund-outline` 生成的大纲，逐节撰写基金申请书的中文正文。核心要求：**说服性学术写作**——不是描述已完成的研究，而是论证为什么这个研究值得资助。

**与论文写作的关键区别**：
- **说服性**：每段都在回答"为什么值得资助"，不是"我做了什么"
- **前瞻性**：研究方案用将来时，描述"将要做什么"而非"做了什么"
- **综合性**：多个源项目的内容需要编织成一条叙事主线
- **简洁有力**：基金评审时间有限，每句话都必须有信息增量

**输入** `$ARGUMENTS`：`section=XXX`（可选，不指定则交互式选择）。

## 步骤 0：前置准备

### 0.1 解析 `$ARGUMENTS`

- 提取 `section` 参数
- 无 `section` → 列出可用章节，AskUserQuestion 询问要写哪个

### 0.2 读取项目配置

- 读取项目 `CLAUDE.md`，获取：
  - 源项目列表及路径
  - 基金类型（国自然面上/青年/重点 等）
  - 输出格式（LaTeX / Word / Markdown）
  - 章节结构

### 0.3 读取大纲文件

- 读取 `sections/` 下对应章节的 `*_outline.md`
- 读取 `sections/synthesis_summary.md`（综合摘要）
- 如大纲文件不存在 → 提示用户先运行 `/fund-outline`

### 0.4 读取源项目材料

```
FOR EACH source_project IN {SOURCE_PROJECTS}:
  a. 读取 {source_project}/structure/0_global/idea.md
  b. 读取 {source_project}/manuscript.tex（按需读取相关章节）
  c. 如有 citation pool → 读取备用
END FOR
```

### 0.5 进度检查

检查 `structure/progress.md`（如存在），了解哪些章节已完成、哪些待写。
- 已完成的章节 → 跳过或提示用户选择是否重写
- 当前章节有草稿 → 询问用户是否基于草稿修改还是重新生成

## 步骤 1：章节路由

根据 `section` 参数，路由到对应的写作模式：

| 章节 | 写作模式 | 字数目标 | 核心策略 |
|:-----|:---------|:---------|:---------|
| 立项依据 | `综合提炼` | 5,000-8,000 | 从多个源项目综合研究现状，铺设逻辑链 |
| 研究内容 | `前瞻规划` | 3,000-5,000 | 将已有成果改写为"计划研究"的表述 |
| 研究方案 | `前瞻规划` | 3,000-5,000 | 方法细节的前瞻性表述 + 技术路线 |
| 创新点 | `成果包装` | 500-1,000 | 精炼、有冲击力的创新点表述 |
| 研究基础 | `成果包装` | 1,000-2,000 | 前期工作包装 + 团队实力展示 |

## 步骤 2：写作执行

### 2.1 写作模式定义

**模式 A：综合提炼**（立项依据）

主要用于将多个源项目的文献综述、研究背景综合为一篇连贯的立项依据。

写作指令要点：
```
- 语体：中文学术申请书体，严谨但不晦涩，有说服力
- 逻辑结构：问题引入 → 现状梳理 → 不足揭示 → 本项目切入
- 引用风格：(Author, Year) 或 Author (Year)，从源项目 bib 中选取
- 段落策略：每段一个论点，段首句是论点句
- 禁止：口语化、过度自夸、空泛表述（如"具有重要意义"不加具体说明）
- 字数严格控制在目标范围内
```

**模式 B：前瞻规划**（研究内容、研究方案）

将源项目中已有的方法/结果改写为"计划研究"的前瞻性表述。

写作指令要点：
```
- 时态转换：已完成 → 将要做（"本项目拟采用…" "将构建…" "计划通过…"）
- 保留方法核心细节，但调整为计划语气
- 突出方法的创新性和必要性（为什么用这个方法而不是别的）
- 研究内容之间的衔接要自然，体现递进关系
- 技术路线需清晰可执行，评审能一眼看懂步骤
- 可行性论证要有理有据（前期基础 / 数据可得性 / 方法成熟度）
```

**模式 C：成果包装**（创新点、研究基础）

将已有成果重新包装为基金语言。

写作指令要点：
```
- 创新点：每条一句核心 + 2-3句展开，对标现有方法的优势
- 创新点排序：理论创新 > 方法创新 > 应用创新
- 前期工作：已发表论文按与本项目的相关性排序
- 用具体成果说话（模型名、方法名、发表期刊）
- 避免空泛的自我评价，用事实论证团队能力
```

### 2.2 逐子节写作

对当前章节的每个子节：

1. **提取大纲要点**：从 `*_outline.md` 读取该子节的结构化要点
2. **提取源材料**：根据要点中的来源标注，从对应源项目读取相关段落
3. **调用 sci-writer-zh agent**：

```
subagent_type: "sci-writer-zh"

prompt 结构：
- 角色：基金申请书写作专家
- 写作模式：{A/B/C}
- 综合摘要：{SYNTHESIS_SUMMARY}
- 当前子节大纲：{子节要点}
- 源材料：{从源项目提取的相关内容}
- 上下文：{已完成的前序子节文本，保持连贯}
- 字数目标：{子节字数}
- 输出：纯中文学术文本
```

4. **展示给用户**：显示生成的文本 + 字数统计 + 来源标注
5. **用户确认**：AskUserQuestion
   - "确认" → 保存并继续下一子节
   - 给出修改意见 → 重新生成或手动调整
   - "跳过" → 标记为待完成，继续

### 2.3 串行写作约束

基金申请书各子节之间逻辑紧密，**必须串行写作**：

```
SET {PRIOR_TEXT} = ""

FOR EACH subsection IN {CURRENT_SECTION_OUTLINE} (SEQUENTIAL):
  a. 生成该子节文本（传入 {PRIOR_TEXT} 作为上下文）
  b. 用户确认后追加到 {PRIOR_TEXT}
  c. 显示进度：[{i}/{N}] {subsection_title} — {word_count}字
END FOR
```

## 步骤 3：后处理

### 3.1 拼接章节文本

将所有确认的子节文本拼接为完整章节：

```
# {章节标题}

{子节1文本}

{子节2文本}

...
```

### 3.2 一致性检查

检查完整章节的：
- **术语一致性**：同一概念在不同子节中的表述是否统一
- **逻辑连贯性**：子节之间的过渡是否自然
- **字数达标**：总字数是否在目标范围内
- **引用完整性**：引用格式是否统一

如有问题 → 指出并提供修改建议，等用户确认后修改。

### 3.3 保存

保存到 `structure/` 对应文件：

