# Fund Draft — 基金申请书逐节撰写

基于 `/fund-outline` 生成的大纲，逐节撰写基金申请书的中文正文。核心要求：**说服性学术写作**——不是描述已完成的研究，而是论证为什么这个研究值得资助。

**与论文写作的关键区别**：
- **说服性**：每段都在回答"为什么值得资助"，不是"我做了什么"
- **前瞻性**：研究方案用将来时，描述"将要做什么"而非"做了什么"
- **综合性**：多个源项目的内容需要编织成一条叙事主线
- **简洁有力**：基金评审时间有限，每句话都必须有信息增量

**输入** `$ARGUMENTS`：`section=XXX`（可选，不指定则交互式选择）。

## 步骤 2：写作执行

### 2.1 写作模式定义

**模式 A：综合提炼**（立项依据）

主要用于将多个源项目的文献综述、研究背景综合为一篇连贯的立项依据。

写作指令要点：
```
- 语体：中文学术申请书体，严谨但不晦涩，有说服力
- 逻辑结构：问题引入 → 现状梳理 → 不足揭示 → 本项目切入
- 引用风格：(Author, Year) 或 Author (Year)，从源项目 bib 中选取
- 段落策略：每段一个论点，段首句是论点句
- 禁止：口语化、过度自夸、空泛表述（如"具有重要意义"不加具体说明）
- 字数严格控制在目标范围内
```

**模式 B：前瞻规划**（研究内容、研究方案）

将源项目中已有的方法/结果改写为"计划研究"的前瞻性表述。

写作指令要点：
```
- 时态转换：已完成 → 将要做（"本项目拟采用…" "将构建…" "计划通过…"）
- 保留方法核心细节，但调整为计划语气
- 突出方法的创新性和必要性（为什么用这个方法而不是别的）
- 研究内容之间的衔接要自然，体现递进关系
- 技术路线需清晰可执行，评审能一眼看懂步骤
- 可行性论证要有理有据（前期基础 / 数据可得性 / 方法成熟度）
```

**模式 C：成果包装**（创新点、研究基础）

将已有成果重新包装为基金语言。

写作指令要点：
```
- 创新点：每条一句核心 + 2-3句展开，对标现有方法的优势
- 创新点排序：理论创新 > 方法创新 > 应用创新
- 前期工作：已发表论文按与本项目的相关性排序
- 用具体成果说话（模型名、方法名、发表期刊）
- 避免空泛的自我评价，用事实论证团队能力
```

### 2.2 逐子节写作

对当前章节的每个子节：

1. **提取大纲要点**：从 `*_outline.md` 读取该子节的结构化要点
2. **提取源材料**：根据要点中的来源标注，从对应源项目读取相关段落
3. **调用 sci-writer-zh agent**：

```
使用 Agent 工具调用 sci-writer-zh agent：
- subagent_type: "sci-writer-zh"
- model: opus
- （不传 isolation 参数——全局红线）

prompt 结构（**所有硬约束字段必须注入**，不可省略）：

## 角色
基金申请书写作专家（不是论文作者，也不是学位论文作者）

## 文本类型硬约束
- 文本类型：中文基金申请书（{国自然青年/面上/重点 / 省基金 / 校级} — 从 CLAUDE.md 读取）
- 与论文/学位论文的区别：**论证"为什么值得资助"，不是描述"已做了什么"**

## 评审视角
目标读者是见过数百份申请书的资深评审专家。预期阅读模式：
- 评审人**快速浏览**，关键信息必须在段首/段末
- 不耐烦读模糊表述、冗余铺垫、空洞论断
- 会**主动寻找**"创新点是否锐利""可行性是否可信""申请人是否匹配"

## 说服性要求（硬约束）
- 每一段落必须回答"为什么值得资助/为什么这样做"，不能只是描述性陈述
- 立项依据段落必须构建"已知 → 未知 → 本项目填补"的逻辑链
- 创新点用锐利陈述句：禁止"一定程度上""有所""有所创新""具有较好的"等弱化词
- 方法方案要给"这个人真的能做出来"的信心

## 时态约束
- 未完成的工作（研究内容、研究方案、预期成果）→ 将来时（"将构建""拟研究""预期得到"）
- 已有成果（研究基础、前期积累、已发表工作）→ 过去时/现在完成时
- 禁止时态混用：模式 B（展开）模式 C（新增）默认将来时

## 写作模式（与本 skill 步骤 2.1 的 A/B/C 定义对齐）
- **模式 A（综合提炼）**：将多个源项目的综述/背景综合为连贯立项依据。结构：问题引入 → 现状梳理 → 不足揭示 → 本项目切入
- **模式 B（前瞻规划）**：将源项目已有方法/结果改写为"计划研究"的前瞻性表述。时态：已完成 → 将要做（"本项目拟采用…""将构建…"）
- **模式 C（成果包装）**：将已有成果重新包装为基金语言。创新点每条一句核心 + 2-3句展开，对标现有方法优势；前期工作按相关性排序
- **模式 D（模板填写，仅经费预算）**：不走 sci-writer-zh，由主 agent 按资助类型经费类目直接填写

## 基金类型专属要求
- 国自然青年：突出申请人潜力与创新性（>35 岁者慎投）
- 国自然面上：突出研究基础与方案可行性
- 国自然重点：突出系统性、团队、重大科学问题
- 省基金：地方需求对接、产学研结合
- 校级：创新性 + 实施可行性（经费小、周期短）

## 输入材料
- 综合摘要：{SYNTHESIS_SUMMARY}
- 当前子节大纲：{子节要点}
- 源材料：{从源项目提取的相关内容}
- 上下文：{已完成的前序子节文本，保持连贯；不重复论述}
- 字数目标：{子节字数}（从 CLAUDE.md `## 章节规划` 读取；严格不超，少 5% 以内可接受）

## 输出要求
- 纯中文学术文本，不带 markdown 标题
- 段落间用空行分隔
- 引用用 `\cite{key}` 格式（不用脚注）
- 结尾附"字数统计"和"模式自检"（是否违反说服性/时态/字数）
```

4. **展示给用户**：显示生成的文本 + 字数统计 + 来源标注
5. **用户确认**：AskUserQuestion
   - "确认" → 保存并继续下一子节
   - 给出修改意见 → 重新生成或手动调整
   - "跳过" → 标记为待完成，继续

### 2.3 串行写作约束

```

  b. 用户确认后追加到 {PRIOR_TEXT}
  c. 显示进度：[{i}/{N}] {subsection_title} — {word_count}字
END FOR
```

## 步骤 3：后处理


### 3.2 一致性检查

检查完整章节的：
- **术语一致性**：同一概念在不同子节中的表述是否统一
- **逻辑连贯性**：子节之间的过渡是否自然
- **字数达标**：总字数是否在目标范围内
- **引用完整性**：引用格式是否统一

如有问题 → 指出并提供修改建议，等用户确认后修改。
