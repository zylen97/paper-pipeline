## 模式 1：Ingest（录入）

触发：`/kb ingest` 或用户在对话中直接发来素材内容

### 1.1 素材来源

素材可来自三种途径：

| 来源 | 处理方式 |
|:-----|:---------|
| **raw/ 目录中的文件** | 读取所有 raw/ 下的 .md/.json/.txt 文件（不含 archive/） |
| **对话中直接发来的文本** | 直接处理，处理完毕后保存一份到 raw/archive/ |
| **Twitter URL** | 通过 web-access 获取推文文本，然后按文本处理 |
| **YouTube URL** | 优先用 `youtube-transcript-api`（Python 库，已装，详见 §1.1.1），失败时**先询问用户**是否回退 web-access。字幕带时间戳落盘到 `raw/{YYYY-MM-DD}_YouTube_{频道名}_{简短标题}.md`，再按文件流程处理 |

### 1.1.1 YouTube 字幕抓取

使用 `youtube-transcript-api`（已装，pip 包 `youtube-transcript-api>=1.2.4`）。

**抓取脚本：**

```python
from youtube_transcript_api import YouTubeTranscriptApi

api = YouTubeTranscriptApi()

# 可选：先列出可用字幕语言
transcript_list = api.list(video_id)
for t in transcript_list:
    print(f"{t.language_code} ({t.language}) {'[auto]' if t.is_generated else '[manual]'}")

# 抓取（语言优先级：中文系 → 英文）
transcript = api.fetch(video_id, languages=['zh-Hant','zh-Hans','zh','en'])
snippets = list(transcript)
```

**关键坑：**
- 新版 API 必须实例化再调 `.fetch()`，不是 `.get_transcript()` 静态方法
- `languages` 列表必须包含 `'zh'`——很多中文视频字幕码是 `zh`，不是 `zh-Hans/zh-Hant`
- 优先级原则：**中文优先，没有中文才用英文**

**文件名规范**（落盘到 `raw/`）：

```
raw/{YYYY-MM-DD}_YouTube_{频道名}_{简短标题}.md
```

示例：`2026-04-14_YouTube_大人的SmallTalk_EP655-AI效率悖论.md`

- 频道名和标题中的空格/特殊字符用连字符 `-` 替换
- 简短标题控制在 20 字以内，保留能唯一识别的关键词

**字幕 md 格式：**

```markdown
---
source: YouTube
url: https://www.youtube.com/watch?v={video_id}
video_id: {video_id}
title: {视频完整标题}
channel: {频道名}
duration_sec: {总时长秒数}
snippet_count: {字幕段数}
fetched_at: {YYYY-MM-DD}
language: {实际抓到的字幕语言码}
---

[0s] 本集節目由大人學贊助提供
[4s] 我想問你一個非常簡單
[6s] 卻也很不簡單的問題
...
```

**失败处理：**

如果 `youtube-transcript-api` 抓取失败（视频无字幕 / 被地区封锁 / API 报错），**必须先询问用户是否回退到 web-access CDP 模式**，不要直接回退：

```
youtube-transcript-api 抓取失败：{具体错误}
视频信息：{title} - {channel}
是否回退用 web-access 打开视频页爬字幕面板？（慢但能应对更多场景）
```

用户确认后才调 web-access。

**归档策略：**

`raw/archive/` **永久保留**所有字幕原文（不自动清理）。纯文本体积小，保留原文对后续写博客引用带时间戳金句很关键。

### 1.2 JSON 格式处理

Twitter 导出的 JSON 格式，每条 tweet 提取 `full_text` 或 `text` 字段。批量处理时逐条分析。

### 1.3 录入流程

对每一条素材，执行以下步骤：

**Step 1 — 阅读与理解**
通读素材，理解核心洞察。

**Step 1.5 — 内容筛选**
在主题判定前，对素材进行内容筛选，过滤不适合进入知识库的内容：

| 过滤类型 | 判定标准 | 示例 |
|:---------|:---------|:-----|
| **色情/两性** | 涉及性行为描述、PUA、约炮、色情消费习惯 | "看片阈值""约会操控术""打飞机" |
| **暴力/犯罪** | 详细描述暴力手法、血腥场面、犯罪细节 | 绑架勒索、暴力伤害的新闻细节 |
| **政治敏感** | 涉及政治隐喻、政治讽刺、敏感政治事件讨论 | 借故事暗喻政治体制、敏感维权事件 |
| **无实质内容** | 经提取后仍无可用文本洞察的内容 | 打开链接后是已删除页面、纯广告、无信息量的 meme |
| **纯情绪宣泄** | 无观点、无洞察的谩骂或抱怨 | 无信息增量的吐槽 |

处理方式：
- 被过滤的素材**不整合到主题文件**
- 移动到 `raw/archive/` 并标注 `> 过滤：{过滤类型} — {原因} | {日期}`
- **必须向用户汇报**：列出所有被过滤的素材及原因，用户可手动覆盖（"这条保留"）
- 用户覆盖后，按正常流程整合到对应主题文件

> **注意**：讨论两性关系的健康观点（如择偶标准、婚恋经营）不属于过滤范围，只过滤色情/PUA/物化内容。同理，讨论社会问题的批判性思考不等于暴力内容。筛选要精准，不要过度过滤。

**纯链接素材的特殊处理**：如果素材只有一个链接（如 X Article、外部文章）而无正文文本，**不直接过滤**。先通过 web-access 打开链接提取实际内容，提取出的文本再走正常的筛选→分类→整合流程。只有提取后仍无实质内容时才过滤。

**Step 2 — 主题判定**
判断素材属于哪个主题文件。如果一条素材涉及多个主题，放到最核心的那个。

| 主题文件 | 适用内容 |
|:---------|:---------|
| 人生哲学 | 顶层设计、存在主义、人生意义、认知智慧、健康 |
| 心态与行动力 | 行动力、自信、拒绝、心态修炼、内心力量 |
| 人际与亲密关系 | 社交、婚恋、友情、性格认知 |
| 事业与科研 | 工作策略、学术、职业发展、Ikigai |
| 投资与消费 | 金钱观、投资、消费主义、房产 |
| 注意力与专注 | 注意力管理、数字极简、专注力 |
| 新技术与AI | AI工具、技术哲学、人与技术关系 |
| Eason | 陈奕迅歌词相关 |

**Step 3 — 整合（不是追加）**

> **核心原则：一个 ## 章节 = 一个提炼后的洞察，不是一条来源。**
> 知识库是洞察笔记，不是语录收藏夹。多条说同一件事的素材应合并为一个章节。

打开对应主题文件，理解现有内容结构。然后判断：

**判断逻辑：**
1. 这条素材表达的洞察，已有章节**已经覆盖**了吗？
   → 是：把素材的独特视角/案例/金句**融入已有章节的论述中**，来源追加到末尾
2. **部分覆盖**？
   → 融入已有章节，同时补充新的维度
3. 是**全新的洞察**？
   → 新建 ## 章节

**章节格式（洞察导向）：**
```markdown
## X.Y 洞察标题（用提炼后的观点做标题，不是原文标题）

用自己的话（Zylen 的视角）写出这个洞察的核心论述。
可以综合多条素材的不同角度，形成一个有层次的段落。
引用原文金句时用 `>` 引用块，但主体是自己的提炼。

**来源：** @作者1, @作者2, @作者3, Twitter

---
```

**示例 — 对比旧模式和新模式：**

❌ 旧模式（语录墙）：
```
## 6.5 别和奴性强的人深交
**来源：** @Morris_LT
别和奴性强的人有太深的交往...
---
## 6.6 零成本接近的人不必太热情
**来源：** @Morris_LT
对于零成本就能接近你的人...
---
## 6.7 善良的标准
**来源：** @Morris_LT
真正的善良：遇强不弱，遇弱不强...
---
```

✅ 新模式（洞察笔记）：
```
## 6.3 人际筛选：不改变、不教育、只筛选

不要试图改变任何人。别和奴性强的人深交，对零成本就能接近你的人不必太热情。真正的善良不是无底线的包容，而是「遇强不弱，遇弱不强，遇善更善，遇恶更恶」。

> 免费教人等于结仇——佛只渡有缘人。

**思考：** 这和决策原则里的「筛选 > 改变」一脉相承。核心不是冷漠，是把有限精力留给值得的人。

**来源：** @Morris_LT ×3, Twitter

---
```

**关键差异：**
- 标题是**提炼后的洞察**，不是原文的复读
- 正文是**自己的话**综合多条素材，不是 copy-paste
- 金句用引用块保留原味，但主体是论述
- 来源合并列在末尾，不是一条一来源
- `**思考：**` 连接到更大的思想体系

**融入已有章节时的操作：**
- 读懂已有章节在说什么
- 判断新素材是否提供了新角度、新案例或新金句
- 如果有，把新内容**编织进**已有论述中（而非追加在末尾）
- 来源列表追加新来源
- 如果新素材只是重复已有洞察且没有新意，**不整合**，记录为"已有覆盖，跳过"

**格式红线（必须遵守）：**
- 每节必须以 `---` 结尾（包括大类标题切换处）
- 禁止空章节：有标题就必须有内容，否则不建这个章节
- 列表/框架不能截断：标题承诺了 N 点就必须写完 N 点，写不完则改标题
- `**来源：**` 行只写来源信息（@作者, 平台），个人评论用 `**思考：**` 单独标注
- 单节建议 ≤1000 字，超长内容应拆为子节（X.Y.1, X.Y.2）
- 同一洞察不得在多个章节重复出现，选最契合的一个放入

**Step 4 — 心智模型检查**
如果这条素材触动了 Zylen 的核心信念、决策原则或审美风格，更新 `_mental-model.md` 的相应部分。大多数素材不会触发模型更新——只有真正影响「我是谁」「我相信什么」的内容才需要更新。

**Step 5 — 日志与归档**
- 在 `_log.md` 记录：日期 | 操作描述 | 影响的文件
- 将已处理的素材文件**移动**（非复制）到 `raw/archive/`，移动前在文件头部添加处理标注：
  ```markdown
  > 整合至：{主题文件} §{编号} | {日期}
  ```
  移动后 raw/ 保持干净——里面有文件 = 还没处理
- 如果素材是对话中直接发来的，保存一份到 `raw/archive/` 留档，格式为 `{日期}_{主题关键词}.md`

### 1.4 批量录入

**少量素材（≤10 条）**：主 agent 逐条执行 Step 1→5，合并日志。

**大量素材（>10 条）**：启用预分类 + 并行整合模式：

**Step 0 — 预分类**
读取 raw/ 中所有待处理素材，按主题关键词自动分类，生成按主题分组的临时文件（如 `推特书签_新技术与AI.md`）。分类逻辑与 Step 2 主题判定表一致。无法判定的素材归入「其他」，由主 agent 在汇总阶段二次分类。

如果 raw/ 中的素材**已经按主题预分类**（文件名含主题名），跳过 Step 0。

**Step 0.5 — 批量筛选**
在分发给 sub-agent 之前，主 agent 快速扫描所有素材，执行 Step 1.5 内容筛选，将敏感内容剔除并汇报给用户。筛选后的干净素材才交给 sub-agent。

**并行整合**
为每个主题文件派一个 sub-agent，各自独立执行 Step 1 → 3（阅读理解 → 整合到对应主题 md）。**跳过 Step 1.5**（筛选已在 Step 0.5 完成），**跳过 Step 2**（主题判定已在 Step 0 完成），**跳过 Step 4**（心智模型检查由主 agent 汇总阶段统一处理）。Sub-agent 的 prompt 必须包含：
- 对应的 raw/ 素材文件路径
- 对应的主题 md 文件路径
- 整合规则（Step 3 的完整要求）
- 来源标注格式和编号规则

**「其他」分类处理**：Step 0 中无法判定的素材归入「其他」文件。并行整合阶段，主 agent 逐条阅读「其他」素材，二次分类后分配到正确的主题 md 中手动整合（量少，不需要单独 sub-agent）。确实无法归类的素材，在汇报中列出供用户决定。

**汇总**
所有 sub-agent 完成后，主 agent 执行：
- **跨文件查重**：扫描所有被修改的主题文件，检查是否有相同内容出现在不同文件中。发现重复则保留最契合的一处，删除其余
- **格式质检**：快速检查所有被修改文件的格式红线（`---` 分隔符、空章节、截断内容、来源标注规范）
- Step 4：通读所有更新后的主题文件，检查是否需要更新 `_mental-model.md`
- Step 5：写日志，将 raw/ 中已处理的文件移动到 `raw/archive/`
- **语录墙检测**：如果本次 ingest 超过 10 条素材，对所有被修改的主题文件执行语录墙检测（检查各二级分类下 ## 是否超过 8 个）。发现超标则在汇报中提醒用户考虑压缩
- 向用户汇报：共处理 N 条素材、各主题文件变更概要、被过滤 / 无法归类的条目清单、质量问题修复清单、心智模型是否有更新、语录墙检测结果（如有）

## 模式 2：Lint（健康检查）

触发：`/kb lint`

### 2.1 检查项

读取所有主题文件和 `_mental-model.md`，检查以下问题：

| 检查项 | 说明 |
|:-------|:-----|
| **矛盾检测** | 不同主题文件之间、或同一文件内部，是否存在说法矛盾？注意区分「真正矛盾」和「刻意保留的张力」（参见心智模型 §六 内在张力） |
| **孤立片段** | 有没有素材放在了不合适的主题下？ |
| **待处理素材** | raw/ 中是否有未处理的文件？ |
| **心智模型同步** | _mental-model.md 是否还准确反映所有主题文件的全貌？有没有新增的核心信念/决策原则未被模型捕捉？ |
| **主题覆盖** | 现有 8 个主题分类是否足够？是否需要新增或合并？ |
| **重复内容** | 同一洞察是否在多个文件或多个章节中重复出现？跨文件和文件内都要检查 |
| **格式规范** | 每个章节是否以 `---` 结尾？是否有空章节（有标题无内容）？`**来源：**` 是否只含来源信息？单个章节是否超过 1000 字？ |
| **内容完整性** | 标题承诺了 N 点/N 层的内容是否全部写完？有无截断的列表或框架？ |
| **敏感内容残留** | 是否有色情/PUA/政治敏感/物化内容残留？（每次 lint 都要检查） |
| **语录墙检测** | 每个 `#` 大类下的 `##` 章节数是否超过 8 个？超过则提醒用户考虑压缩——合并表达同一洞察的章节。检查是否有多个 `##` 说的是同一件事但各自独立成章节 |

### 2.2 输出格式

```markdown
## 知识库健康报告 — {日期}

### 状态概览
- 主题文件：8 个
- 总条目：约 X 条
- raw/ 待处理：N 条
- 上次 lint：{日期}

### 发现的问题
1. [矛盾] {文件A §X} vs {文件B §Y}：{描述}
2. [待处理] raw/ 中有 N 个文件未整合
3. ...

### 建议操作
1. {建议1}
2. {建议2}
```

用户确认后再执行修复。

## 模式 3：Model（心智模型）

触发：`/kb model`

### 3.1 查看模式

如果没有附加参数，读取并展示 `_mental-model.md` 的当前内容，附带：
- 最后更新时间
- 版本号
- 自上次更新以来新增的素材条数

### 3.2 更新模式

`/kb model update` — 重新通读所有主题文件，与当前心智模型对比，识别需要更新的部分：

- 新增的核心信念
- 需要调整的决策原则
- 新的内在张力
- 性格自知的新发现

更新后递增版本号（v1.0 → v1.1），更新日期。

**重要**：心智模型的更新需要向用户展示 diff，用户确认后才写入。

## 注意事项

1. **素材的来源标注必须保留**。每条内容必须有 `**来源：**` 行，注明原作者和平台。
2. **Zylen 的原创思考用 `**思考：**` 标注**，与引用素材明确区分。
3. **不要过度整合**。如果一条素材表达的是一个独立的、与现有章节不重叠的洞察，应独立成章节。但如果多条素材说的是同一个洞察，必须合并而非各自独立。判断标准是洞察是否独立，不是来源是否独立。
