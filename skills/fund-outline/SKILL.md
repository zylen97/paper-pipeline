# Fund Outline — 基金申请书大纲生成

从 2-3 个已有科研项目中**综合提炼**，为基金申请书各章节生成结构化大纲。核心挑战是将多个独立研究项目编织成一个逻辑自洽、前后呼应的研究计划。

**输入** `$ARGUMENTS`：无（交互式启动）。

## 步骤 0：前置准备

### 0.1 读取项目 CLAUDE.md

- 读取当前基金项目的 `CLAUDE.md`
- 从 `## 章节规划` 表格读取章节列表（编号、名称、目标字数）。后续步骤按此列表动态执行，不硬编码章节数。
- 提取以下关键信息：
  - **源项目列表**（source projects）：各源项目的路径
  - **章节结构**（section structure）：从章节规划表读取，非硬编码
  - **基金类型**（fund type）：国自然面上/青年/重点 等
  - **学科领域**：用于判断字数规范和写作惯例

### 0.1.5 阶段检查

开始时如项目阶段为 `literature`，更新 CLAUDE.md 的 `## 项目阶段` 为 `outlining`。

### 0.2 读取源项目材料

对每个源项目（source project），读取以下文件：

```
FOR EACH source_project IN {SOURCE_PROJECTS}:
  a. 读取 {source_project}/CLAUDE.md → 了解项目阶段和结构
  b. 读取 {source_project}/structure/0_global/idea.md → 提取 Gap/RQ/方法/贡献
  c. 读取 {source_project}/manuscript.tex → 提取正文结构、核心论点、方法细节
  d. 如有 {source_project}/structure/2_literature/ → 提取文献综述素材
END FOR
```

汇总为 `{SOURCE_MATERIALS}`，包含每个源项目的：
- 研究问题（RQ）
- 理论框架 / 方法论
- 核心发现 / 贡献
- 关键文献

### 0.3 生成项目综合摘要

基于 `{SOURCE_MATERIALS}`，生成一份综合摘要（`{SYNTHESIS_SUMMARY}`），初步回答：

1. **统一主线**：这 2-3 个项目之间的内在逻辑关联是什么？
2. **递进关系**：它们如何构成一个递进/互补/系统性的研究计划？
3. **共同 Gap**：它们共同指向的更大学术空白是什么？
4. **升华后的总目标**：超越单个项目，整体研究计划要回答的核心问题是什么？

展示 `{SYNTHESIS_SUMMARY}` 给用户，等待确认或修改。

> **动态执行说明**：以下步骤策略按国自然结构编写。对省基金/校级基金项目，根据 CLAUDE.md 章节列表动态调整：合并章节使用合并后的策略，缺少的章节跳过。输出文件名始终与 fund-init 创建的章节文件对应：`sections/{NN}_{章节名}_outline.md`。

## 字数与章节集合的权威来源

**硬约束**：所有步骤中出现的"字数目标"参考值仅为**国自然参考区间**，真实目标必须从项目 CLAUDE.md `## 章节规划` 对应表格读取（fund-init 已按基金类型写入三张表之一）。若步骤文字与 CLAUDE.md 不一致，**以 CLAUDE.md 为准**。

**章节集合**：
- **国自然**：8 章（01 立项依据 / 02 研究目标 / 03 研究内容 / 04 研究方案 / 05 创新点 / 06 可行性分析 / 07 研究基础 / 08 经费预算）—— outline 文件也按 8 节对齐 fund-init 章节编号
- **省基金**：6 章（按 CLAUDE.md 省基金表，涉及合并节）
- **校级**：4 章（按 CLAUDE.md 校级表）

**outline 文件命名**：与 fund-init 的章节文件严格一一对应，仅加 `_outline.md` 后缀。例如 fund-init 创建 `sections/02_研究目标.md` → fund-outline 产出 `sections/02_研究目标_outline.md`（不再用 `01/02/03/04/05` 乱序编号）。

**不产 outline 的章节**：经费预算（08）通常是填表格式，不需要叙述 outline——改为"引导用户按模板直接填写 sections/08_经费预算.md"，不生成 outline 文件。但 fund-draft 步骤 0.3 必须对此类章节做"允许无 outline"分支（见 fund-draft Step 0.3）。

## 步骤 1：立项依据大纲（01_立项依据_outline.md，字数见 CLAUDE.md）

> **注意**：各章节目标字数从 CLAUDE.md `## 章节规划` 读取，以下数值仅为国自然参考值。国自然青年基金正文总字数一般不超过 8,000 字。各节字数应按此上限合理分配，立项依据通常控制在 3,000-4,000 字。

### 1.1 研究背景与意义

从源项目的 Introduction / idea.md 中提炼：

- **实践背景**：该领域面临的现实问题（从各源项目的 motivation 综合）
- **理论背景**：现有理论的发展脉络
- **研究意义**：理论意义 + 实践价值（升华到基金层面，比单篇论文更宏观）

生成要点列表，每个要点标注来源项目。

### 1.2 国内外研究现状

从源项目的 Literature Review / citation pool 综合：

- **分方向梳理**：按研究主题分 3-5 个方向，每个方向：
  - 代表性成果（从各源项目的引用中选取）
  - 发展趋势
  - 不足之处
- **综合评述**：现有研究的整体不足（为后文铺路）
- **引用策略**：标注可复用的 citation key

### 1.3 关键科学问题

- 从各源项目的 Gap 中提炼 2-3 个**关键科学问题**
- 展示逻辑链：现状不足 → 科学问题 → 本项目切入点

### 1.4 展示与确认

以结构化大纲形式展示立项依据，标注：
- 每个要点的来源项目
- 综合逻辑（哪些是直接复用，哪些是升华/综合）
- 预估字数分配

**AskUserQuestion**：等待用户逐条确认或修改。

## 步骤 2：研究目标与研究内容大纲（02_研究目标_outline.md + 03_研究内容_outline.md，字数见 CLAUDE.md）

> 国自然下拆分为两个 outline 文件（对应 fund-init 章节 02、03）；省基金的"研究目标与内容"合并节则合并为一个 outline 文件，文件名同 fund-init 的 sections/{合并节} 对应。

### 2.1 总体研究目标

- 从 `{SYNTHESIS_SUMMARY}` 的升华目标出发
- 一段话概括整个研究计划要达到的目标

### 2.2 具体研究内容

每个源项目贡献一个研究内容模块：

```
研究内容一：{源项目A的核心贡献，重新包装为基金语言}
  - 研究对象
  - 研究方法
  - 预期成果

研究内容二：{源项目B的核心贡献}
  ...

研究内容三：{源项目C的核心贡献 或 A+B的延伸}
  ...
```

**关键**：研究内容之间必须有递进/支撑关系，不能是割裂的三块。展示内容间的逻辑关联图。

### 2.3 拟解决的关键问题

- 从步骤 1.3 的科学问题细化为具体的技术/方法/理论问题
- 每个关键问题对应至少一个研究内容

### 2.4 展示与确认

展示研究内容大纲 + 内容间关联图。

**AskUserQuestion**：等待用户确认。

## 步骤 3：研究方案大纲（04_研究方案_outline.md，字数见 CLAUDE.md）

### 3.1 技术路线

- 从各源项目的 methodology 章节提取方法步骤
- 重新组织为一条完整的技术路线（按研究内容一→二→三的顺序）
- 标注各步骤的输入/输出关系
- 生成技术路线图描述（后续可用 `/figure` 生成 TikZ 图）

### 3.2 各研究内容的具体方案

对每个研究内容：
- 理论基础 / 模型构建 / 数据来源
- 具体方法步骤（从源项目 manuscript.tex 的 methodology 提取，调整为前瞻性表述）
- 预期结果

### 3.3 可行性分析

- **理论可行性**：方法论基础
- **技术可行性**：从源项目已有成果证明方法可行
- **数据可行性**：数据来源和获取途径
- **团队可行性**：前期积累

### 3.4 展示与确认

**AskUserQuestion**：等待用户确认。

## 步骤 4：创新点大纲（05_创新点_outline.md，字数见 CLAUDE.md）

### 4.1 提炼创新点

从各源项目的 contributions 中提炼 3-4 个创新点：

- **理论创新**（至少 1 个）：新框架 / 新视角 / 理论扩展
- **方法创新**（至少 1 个）：新模型 / 新算法 / 方法改进
- **应用创新**（可选）：新场景 / 新发现

每个创新点：
- 一句话概括
- 对标现有方法的优势
- 来源项目标注

### 4.2 展示与确认

**AskUserQuestion**：等待用户确认创新点的表述和排序。

## 步骤 5：研究基础大纲（07_研究基础_outline.md，字数见 CLAUDE.md）

### 5.1 前期工作基础

将源项目的成果包装为"前期工作"：

- 已发表/在审论文列表
- 各论文与本项目研究内容的对应关系
- 已有模型/数据/代码基础

### 5.2 团队条件

- 申请人学术背景
- 团队成员分工
- 实验/计算条件

### 5.3 展示与确认

**AskUserQuestion**：等待用户确认。

## 步骤 5.5：可行性分析大纲（06_可行性分析_outline.md，字数见 CLAUDE.md）

> 国自然独立章节；省基金/校级若与创新点合并则由前序步骤覆盖，本步骤跳过。

与用户交互式确认以下 3 个维度的论据结构：

1. **学术/理论可行性**：所用理论基础是否成熟、前序研究（自己 + 他人）是否已验证
2. **技术/方法可行性**：数据可得性、实验/仿真环境、算法/模型的工程落地性
3. **团队/条件可行性**：申请人/合作者的研究积累（链接 07_研究基础）、单位条件、经费支持

输出 outline 时为每个维度列出 2-4 条具体论据（来自源项目已有成果或指南要求），并标记哪些论据已落地、哪些需补充。

## 步骤 5.6：经费预算（08_经费预算.md，**不生成 outline**）

> 经费预算是填表格式，不适合叙述 outline。本步骤仅**提示用户**直接按基金指南模板填写 `sections/08_经费预算.md`：
>
> - 设备费 / 材料费 / 测试化验加工费 / 燃料动力费 / 差旅费/会议费/国际合作与交流费 / 出版/文献/信息传播/知识产权事务费 / 劳务费 / 专家咨询费 / 间接费用
> - 每项写金额 + 必要性简述（2-3 句）
>
> fund-draft 步骤 0.3 对此章设有"允许无 outline"分支，会从 fund-idea.md 和源项目经费信息推断草稿。

## 步骤 6：保存与汇总

### 6.1 保存大纲文件

将各章节大纲保存到项目的 `sections/` 目录（与 `/fund-init` 创建的章节文件同级）：

示例（**国自然 8 节**，与 fund-init NSFC 目录对齐；省基金/校级按实际节数）：

```
sections/
├── 01_立项依据_outline.md
├── 02_研究目标_outline.md
├── 03_研究内容_outline.md
├── 04_研究方案_outline.md
├── 05_创新点_outline.md
├── 06_可行性分析_outline.md
├── 07_研究基础_outline.md
├── 08_经费预算_outline.md         # 可选，实际字数通常零；/fund-draft 自定义生成
└── synthesis_summary.md
```

> **跨基金类型适配**：实际产出文件数与 fund-init 创建的章节文件一一对应；省基金约 5 节（02/04 合并为 `02_研究目标与内容`、03/06 合并为 `03_研究方案与技术路线`），校级约 4 节（更激进合并）。**务必以 fund-init 创建的 `sections/*.md` 实际清单为准**，不要把国自然 8 节清单套到省基金/校级项目上。

每个大纲文件包含：
- 章节标题
- 结构化要点（含来源标注）
- 字数目标
- 用户确认的修改意见（如有）

### 6.2 完成提示

显示：
- 各章节大纲完成状态
- 各章节预估字数 / 总字数
- 源项目素材利用情况（哪些内容被复用、哪些需要新写）
- 综合逻辑线索图
- 提示：运行 `/fund-draft` 逐节撰写正文

### 6.3 阶段转换（仅入场）

本 skill 只负责入场转换：**开始时若阶段为 `literature` → 改为 `outlining`**（已在步骤 0/25 行完成）。

**结束时不触发下一次转换**——`outlining → drafting` 由 `/fund-draft` 首次启动时负责（阶段转换单一责任方原则，避免 fund-outline 和 fund-draft 双写同一字段）。

向用户提示："大纲已完成，运行 `/fund-draft` 进入写作阶段。"
