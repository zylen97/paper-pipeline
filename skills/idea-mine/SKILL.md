## 核心使命

读取当前目录下的一组学术论文PDF，围绕用户指定的**一个目标方向**和**目标期刊**，通过"结构化精读 → idea生成（交叉组合+情境迁移）→ 审稿人质控 → 排序输出"四阶段Pipeline，产出可直接灌入 `init-paper` 骨架的 idea.md 内容。

## 核心预设条件

**中文论文 = idea 池，不是已发表文献。** 在整个 pipeline 中，输入的中文/英文论文仅作为 idea 素材来源，不视为已发表的竞争文献。评估创新性时，参照系**只有英文文献**：这个 idea 在英文学术圈有没有人做过？对英文期刊审稿人来说是不是新的？中文论文中已发表的方法/发现不构成"已被做过"的判据。

## 参数解析

通过两步交互获取参数：

**第一步：目标方向**

使用 AskUserQuestion 询问目标方向（自由文本输入）：
```
请输入目标迁移方向（一句话描述），例如：
- 建设工程管理
- 制造业供应链可持续
- 智慧城市与碳管理
- 应急管理与城市韧性
```

记录为 `{DIRECTION}`。

**第二步：目标期刊**

读取 `~/.claude/skills/idea-mine/journals.md` 中的期刊池，展示完整列表，让用户输入编号多选（2-4个）：

```
请从以下期刊池中选择 2-4 个目标期刊（输入编号，逗号分隔，如 3,6,14）：

1.  Cities                                          #城市
2.  Habitat International                           #城市 #可持续
3.  Journal of Cleaner Production                   #城市 #可持续
...
（完整列表从 journals.md 读取）
```

记录为 `{JOURNALS}`。

**快捷方式**：如果用户在 `$ARGUMENTS` 中直接传入了方向和期刊编号（如 `/idea-mine 建设工程管理 -> 6,13,14`），则跳过交互直接解析。`$ARGUMENTS` 的值为：`$ARGUMENTS`

## 前置检查

1. 扫描当前工作目录及其子目录中的 **PDF 文件**（`**/*.pdf`）
2. 统计 PDF 数量并列出文件清单
3. 如果 PDF 数量为 0，停止并提示用户放入论文
4. 根据 PDF 数量给出建议：
   - **< 10 篇**：警告交叉组合空间不足，建议补充至 12 篇以上，尤其注意方法论多样性
   - **10-20 篇**：甜蜜点（15篇左右最优），直接运行
   - **21-25 篇**：可以运行，提示"论文较多，注意力可能摊薄"
   - **> 25 篇**：建议用户分两批运行（每批 12-18 篇），或自行预筛至 20 篇以内。如用户坚持一次跑完，则执行但警告质量可能下降
5. 向用户确认：`发现 N 篇论文，目标方向：{DIRECTION}，目标期刊：{JOURNALS}。开始挖掘？`

## Pipeline 执行

严格按以下四个阶段顺序执行。

---

### 阶段一：结构化精读（并行 subagents）

**目标**：提取每篇论文的可迁移idea内核。

将 PDF 按每组 3 篇分组，启动并行 Agent（subagent_type: general-purpose），每个 Agent 的 prompt 如下：

```
你是一名管理科学与工程方向的高级研究助理。请全文精读以下PDF论文，对每篇论文提取以下信息：

1. **一句话核心idea**：剥离具体行业情境后，这篇论文的可迁移学术贡献是什么？
2. **方法论标签**：博弈论/演化博弈/实证DID/面板回归/优化/预测/综述/DSGE/微分博弈/...
3. **核心机制标签**：倒U型/溢出效应/信息不对称/政策协同/委托代理/竞合博弈/...
4. **理论框架**：使用了什么理论？（如Weitzman框架、Hotelling模型、委托代理等）
5. **关键发现**（3条以内）
6. **核心创新点**（2-3个，区分理论创新、方法创新、发现创新——这是迁移的核心素材）
7. **研究情境/行业背景**：这篇论文研究的是什么行业/领域的什么问题？（2-3句话，帮助判断情境迁移的可行性）
8. **模型/方法的关键假设**：博弈论的核心假设、实证的识别策略、优化的约束条件等（帮助判断方法迁移后假设是否还成立）
9. **数据来源与样本特征**：用了什么数据、样本量多大、时间跨度、数据库来源（帮助审稿人评估可行性）
10. **原论文 Story 线索**：用3-5句连贯叙述串联"实践痛点 → 文献gap → RQ → 方法选择 → 核心发现 → 贡献声明"的完整逻辑链（不要分点列，要体现逻辑链的连贯性，帮助判断迁移后story该怎么重构）
11. **我识别的未回答问题/盲区**（作者没提到但存在的gap）

每项信息**宁可详细不可遗漏**，允许展开到2-3句话，不要压缩成一句。关键发现和核心创新点尤其要具体，包含具体的变量关系、非线性形式、边界条件等细节。请逐字逐句仔细阅读，不要遗漏任何重要细节。

论文列表：
[论文路径列表]
```

**失败处理**：如果某组 subagent 返回错误（如 API 连接失败），自动重试一次。重试仍失败则跳过该组，在论文摘要表中标注哪些论文未能成功读取，并提醒用户。Pipeline 继续执行（已成功读取的论文仍参与后续阶段）。

**汇总**：收集所有 Agent 的返回结果，整理为**论文摘要表**。

**论文摘要表完成后，输出方法论分布统计**，让用户确认论文池的方法论覆盖度：

```markdown
## 论文池方法论分布

| 方法论类型 | 篇数 | 论文 |
|-----------|------|------|
| 博弈论/机制设计 | N | 论文A, 论文B, ... |
| 实证因果推断(DID/IV) | N | ... |
| 演化博弈/仿真 | N | ... |
| 优化/预测 | N | ... |
| 综述/框架 | N | ... |
| 其他 | N | ... |
```

仅展示分布统计，不做判断性提醒（用户可能故意选同类方法论文来做创新点互补）。

### 阶段 1.5：目标期刊综合画像调研

在正式生成 idea 之前，用 WebSearch 对 `{JOURNALS}` 中的每个期刊进行综合画像调研：

**调研内容**（每个期刊）：
1. **Aims & Scope**：期刊定位、接收什么类型的研究
2. **研究主题热点**：近2年高引/高下载论文的主题方向
3. **方法论接收范围**：明确列出该期刊接收哪些方法论类型（从 Aims & Scope 和近期发表论文中提取），不做占比分布的三档划分（避免对博弈论等小众方法产生有偏估计）
4. **特殊要求**：如 practical implications、policy relevance、行业特殊性论证等

**搜索策略**：
- `"{期刊名}" aims and scope`
- `"{期刊名}" most cited recent articles`
- `"{期刊名}" guide for authors`

**输出格式**：

```markdown
## 目标期刊综合画像

### {期刊名1}
- **Aims & Scope**：{一段话概括}
- **近期热点主题**：{3-5个关键主题}
- **接收的方法论类型**：{列出所有接收的方法论，如：实证DID、面板回归、博弈论、SEM、案例研究、优化模型...}
- **特殊要求/偏好**：{如有}

### {期刊名2}
（同上结构）
```

**此画像的用途**：
- **不约束方法论选择**（方法跟随源论文）
- 在阶段三中供各审稿人参考：审稿人根据自己期刊的画像，独立判断 idea 与期刊的适配度，体现在发表概率评分中
- 同时用于动态生成各审稿人的人设（特殊关注点来自画像中的"特殊要求/偏好"）

### 阶段二：Idea 生成（面向目标方向）

**目标**：生成 **20+ 个**候选 idea，**全部指向 `{DIRECTION}`**。

#### 前置：情境知识补充

在生成 idea 之前，先用 WebSearch 快速检索：
- `{DIRECTION}` 领域近2年的研究热点和前沿问题
- `{JOURNALS}` 期刊近1年的高引/高下载论文主题
- 目标领域是否已有类似迁移研究（避免撞车）

将检索结果作为后续三步的背景知识。

#### 第一步：单篇扫描（1+0 单篇直接迁移）

逐篇扫描论文摘要表，判断每篇论文的 idea 能否**独立迁移**到 `{DIRECTION}` 领域。

判断标准：
- idea 内核在目标领域确实未被充分探索（**参照系仅为英文文献**，中文论文是 idea 池不构成"已被做过"）
- 中文→英文跨语言迁移不存在抄袭问题，不需要担心这一点
- 只需评判：迁移后的**贡献够不够**、**期刊适配度**如何

产出：N 个单篇迁移候选（数量不设上限，有多少算多少）。

#### 第二步：双篇组合（1+1）

扫描论文摘要表中所有论文对（C(N,2)），寻找**互补组合**。每个组合**同时评估**"组合后的 idea 能否落地到 `{DIRECTION}`"。

互补关系的四种类型：
- **方法论互补**：A是博弈论，B是实证DID → A的博弈模型可以用B的实证策略来验证，或反过来
- **机制互补**：A研究了"X→Y"，B研究了"Y→Z" → 两个机制串联成新因果链
- **理论框架互补**：A用了理论甲，B用了理论乙 → 两个lens叠加产生新洞见
- **创新点互补**：A发现了非线性关系，B首创了某个建模框架 → 非线性发现 + 新框架 = 新研究问题

筛出 **15 个**有潜力的 1+1 组合（宁多勿少）。对每个组合标注：**"这个组合缺什么能更强？"**

1+1 组合的创新性判断标准：
- 单独看每篇论文，其贡献已被做过
- 但两者结合后产生了**新的研究问题**，而非简单叠加
- 组合有清晰的逻辑链（A贡献了什么 + B贡献了什么 → 为什么产生新问题）

产出：15 个双篇组合候选。

#### 第三步：增强（为第一步和第二步的候选寻找"小点"）

对第一步和第二步产出的所有候选，分别在剩余论文池中寻找能贡献**"一个小点"**的论文来增强 idea。增强论文不需要贡献完整框架，只需贡献以下任意一种"小点"：

- **一个调节变量/边界条件**（如倒U型、门槛效应、异质性分组依据）
- **一个理论lens**（如委托代理、信号理论、资源依赖理论）
- **一个方法论补充**（如用C的内生性处理策略/识别策略加强A+B的因果推断）
- **一个非线性机制**（让线性story变成非线性story，更有趣）
- **一个情境特殊性论证**（用C的发现来支撑"为什么目标领域和原领域会有不同的理论预测"）

**3a：单篇迁移增强（1+0 → 1+1）**

对第一步的每个单篇候选，在论文池中找一篇"小点"来增强。
- 找到 → 升级为 **1+1 增强版**
- 没找到 → 保留 **1+0**

**3b：双篇组合增强（1+1 → 1+1+1）**

对第二步的每个双篇候选，在剩余论文池中找第三篇"小点"来增强。
- 找到 → 升级为 **1+1+1**
- 没找到 → 保留 **1+1**

**增强后的版本比原始版本创新性加分 +0.5**（无论是 1+0→1+1 还是 1+1→1+1+1）。

#### 合计

第一步（单篇迁移，含3a增强）+ 第二步（双篇组合，含3b增强）= **20+ 个候选**，全部进入阶段三审稿。

#### 迁移创新性判断标准（全局适用）

所有 idea 都涉及向 `{DIRECTION}` 的迁移，统一适用以下判断（**参照系仅为英文文献**，中文论文是 idea 池不构成"已被做过"）：
- idea 内核在目标领域确实未被充分探索（以英文文献为准）
- **情境差异能产生与原论文不同的理论预测** → 创新性升级
- **理论预测方向与原论文一致** → 创新性降级（但不自动 reject，单篇迁移中文→英文本身有价值）
- 目标领域有足够的数据/案例支撑落地

#### 每个 idea 的输出格式

```markdown
### Idea {N}: {一句话标题}

- **来源**：{单篇迁移(1+0) / 单篇迁移增强(1+1) / 双篇组合(1+1) / 双篇组合增强(1+1+1)} — {源论文citation}
- **研究问题**：{展开描述，包含核心变量关系和预期方向，不限一句话}
- **创新逻辑**：{100-150字，说清楚每篇源论文贡献了什么、为什么组合/迁移后产生新价值}
- **目标期刊**：{JOURNALS}（用户选中的所有期刊）
- **方法论**：{具体方法}（来自源论文X的主框架方法）
  - 核心假设在目标领域是否成立：{初步判断}
- **init-paper 方法类型**：{modeling / survey-sem / panel-regression}
- **预期核心发现/命题**：{2-3条，让审稿人能判断"做出来会是什么样"}
- **数据/案例可行性**：{展开说明——数据从哪来、样本怎么构建、有没有现成的数据库}
- **初步 Story 线索**：{一段话梗概，串联"目标领域实践痛点 → gap → RQ → 方法 → 预期贡献"，为审稿人提供评判 story 完整度的直接依据}
```

**注意**：这是审稿人评审的核心对象，每项信息必须足够详细，不能一笔带过。审稿人拿到的就是这段内容。

**方法论选择的决策优先级**：
1. **源论文方法**（最高优先级）→ 用户选中的论文代表用户认可其方法，idea 的主框架方法跟随源论文。对于 1+1 或 1+1+1 组合，以贡献主框架的那篇论文的方法为准
2. **数据/模型可行性** → 该方法在目标领域能否落地（数据可得性、建模条件）。如果可行性存疑，不换方法，而是在可行性维度扣分

### 阶段三：审稿人质量控制

**目标**：以目标期刊审稿人身份对每个 idea 做严格评估。

#### 角色设定（多审稿人，动态适配目标期刊）

每个 idea 由用户选中的**所有期刊（2-4个）**的审稿人分别独立评审（交叉验证）。用户选了几个期刊就启动几个审稿人，全覆盖，不做预选。

**实现方式**：为每个 idea 启动 **N 个独立的 Agent**（subagent_type: general-purpose，N = 用户选中的期刊数），每个 Agent 扮演对应期刊的审稿人。所有 Agent **互不知晓其他审稿人的评分结果**，确保独立性。

每个审稿人的人设根据阶段 1.5 的期刊画像**独立生成**（关注点不同）。prompt 模板：

```
你现在是 {期刊名} 的资深审稿人（Associate Editor 级别）。你见过太多
"换个情境重做一遍"的投稿，对真正的创新有极高的辨别力。

重要预设：你评审的这些 idea 来源于一个非公开的 idea 池（不是已发表文献），
因此不存在"这个已经被做过"的问题。你只需从英文学术圈的视角判断这个 idea
是否有创新性和贡献。

作为该期刊的审稿人，你特别关注：
{根据该期刊画像动态生成 2-3 条特殊关注点，例如：}
{JCLP: practical implications 是否具体可落地、policy relevance、环境效益是否可量化}
{JCEM: construction industry 特殊性论证、工程数据来源可信度、对实践者的决策建议}
{SCS: 城市尺度的数据和案例、与可持续发展目标(SDGs)的关联、跨学科视角}

你需要对以下 idea 做出评判：
1. 如果这个 idea 投到你审的期刊，你会 Reject / Major Revision / Minor Revision？
2. 审稿人最可能 challenge 的 1-2 个核心问题是什么？
3. 作者如何预防性地回应这些 challenge？
```

#### 五维度评分（每项 1-10 分）

| 维度 | 1-3分 | 4-6分 | 7-10分 |
|------|-------|-------|--------|
| **创新性** (Innovation) | 简单换情境/拼凑 | 有一定新意但非突破 | 打开新的研究方向 |

> **创新性评分注意**：参照系仅为英文文献，中文论文作为 idea 池不构成"已被做过"的判据。
| **贡献** (Contribution) | 对理论和实践都没有明确推进 | 拓展了现有理论框架或有一定实践指导意义 | 理论突破+实践价值兼备 |
| **方法可行性** (Feasibility) | 数据不可得/模型不可解 | 有挑战但可克服 | 数据现成/方法成熟 |
| **时效性** (Timeliness) | 过时话题 | 常规热点 | 踩中政策窗口/前沿热点 |
| **发表概率** (Publishability) | <10% | 30-50% | >70% |

#### 每个 idea 的评估流程

**第一步：多审稿人量化评分**（N 个独立 subagent 各自完成，互不知晓其他审稿人结果）

每个审稿人独立输出五维度评分表 + 综合分 + 初审判定（Reject/Major/Minor，凭专业判断，不与分数机械绑定）。

**第二步：六维度定性评估报告**（基于所有审稿人的评分结果综合撰写）

按递进关系组织六个维度，定性报告**必须与量化评分保持一致**——如各审稿人评分有分歧，定性报告必须解释分歧的原因。

**第三步：期刊推荐结论**

#### 每个 idea 的独立 md 文件结构

每个 idea 生成一个独立 md 文件（用 subagent 并行生成，每个 agent 负责几个 idea），结构如下：

```markdown
# Idea {N}: {标题}

## 基本信息

- **来源**：{单篇迁移(1+0) / 单篇迁移增强(1+1) / 双篇组合(1+1) / 双篇组合增强(1+1+1)} — {源论文citation}
- **研究问题**：{展开描述，包含核心变量关系和预期方向}
```

### 阶段四：排序输出 + 独立 md 文件

**目标**：在对话框展示排名表，同时为每个 idea 生成独立 md 文件到统一文件夹。

#### 4.1 对话框输出：排名表

在对话框中展示排名表供用户快速浏览：

```markdown
## 最终排名

| 排名 | Idea | {期刊1}综合 | {期刊2}综合 | ... | 平均综合 | 推荐期刊 |
|------|------|-----------|-----------|-----|---------|---------|
| 1 | ... | X/80 | X/80 | ... | X/80 | {期刊X} |
| ... | ... | ... | ... | ... | ... | ... |
```

**说明**：每个选中期刊各一列综合分（综合分 = 创新×2 + 贡献×2 + 可行×1.5 + 时效×1 + 发表×1.5，满分80）。平均综合 = 所有审稿人综合分的平均值。默认按平均综合分降序排列，但用户可自行按某个期刊的分数或分项维度判断优先级。各 idea 的详细评估报告见独立 md 文件。

#### 4.2 文件夹输出：独立 md 文件

在当前工作目录下创建文件夹，每个 idea 一个独立 md 文件：

```
idea-output_{DIRECTION}_{DATE}/
├── 00_排名总览.md              ← 排名表 + 论文摘要表 + 方法论分布 + 期刊画像
├── 01_idea_{标题简称}.md       ← idea 1 的完整评估报告（结构见阶段三）

├── ...
└── {N}_idea_{标题简称}.md
```

**00_排名总览.md** 包含：阶段一的论文摘要表、方法论分布统计、阶段 1.5 的期刊画像、最终排名表。

**每个 idea 的 md 文件**按阶段三定义的结构输出（基本信息 → 多审稿人量化评分 → 六维度定性报告 → 期刊推荐）。**仅 Top 5 的 md 文件**在末尾附加 init-paper-ready 的 idea.md 内容。

**Top 5 idea.md 部分的关键约束**：
- idea.md 中只写"为什么"和"方向"，不写具体公式/推导/数值
- Gap/RQ 表必须有 2-3 行，不能只有 1 行
- 风险评估表必须包含阶段三审稿人识别的 challenge
- idea.md 严格遵循 init-paper 的 idea.md 模板格式（§1灵感来源 §2背景→Gap→RQ §3方法论 §4贡献 §5风险）

**生成方式**：用 subagents 并行生成，每个 agent 负责几个 idea 的完整 md 文件。

#### 4.3 下一步操作建议（自动衔接 init-paper）

输出完成后，提示用户：
```
请选择一个 idea（输入排名编号），并告诉我：

```

用户选择后，根据该 idea 的评估结果**预填默认参数**，让用户确认：
```
根据该 idea 的评估结果，预填以下参数：
- 出版社：{根据推荐期刊的 @publisher 标签从 journals.md 自动推断}
- 方法类型：{来自 idea 的 init-paper 方法类型字段}
- 目标期刊：{期刊推荐结论中最推荐的期刊}

请确认或修改以上参数。
```

**出版社推断规则**：
- 读取 journals.md 中推荐期刊的 `@publisher` 标签
- init-paper 支持的五种出版社：`@elsevier`/`@asce`/`@emerald`/`@sage`/`@ieee`，直接预填
- 如果未来出现不在以上五种中的标签，提示用户手动选择

```

② 运行 /init-paper {编号}（传入确认后的出版社和方法类型，跳过重复交互）

```

**到此为止**，后续的文献工作流（/lit-plan → /lit-review → /lit-tag → /lit-pool）由用户在项目目录中自行启动。

## 质量红线

以下情况必须在审稿阶段**直接标记为 Reject**，不进入 Top 5：

1. **纯翻译级迁移**：单篇迁移中，迁移后无法产生任何新的理论预测或实践洞见（中文→英文跨语言本身不构成抄袭，但仍需有足够贡献）；双篇/三篇组合中，只是简单叠加没有化学反应
2. **方法不匹配**：迁移的方法在目标领域缺乏数据支撑或理论基础
3. **已被做过**：WebSearch 发现**英文**目标期刊近3年有高度相似的论文（中文论文不算"已被做过"）
4. **"so what" 问题**：即使做出来，对理论和实践都没有明确的推进
5. **超出能力边界**：需要的数据完全不可得，或方法论门槛过高
